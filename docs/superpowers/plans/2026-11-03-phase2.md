# Phase 2 implementation plan

Goal: extend the functioning Phase 1 package into a six-model, matched-input research engine.
Spec: docs/PHASE2_REQUEST.md. Python >=3.12, uv, NumPy/Pandas/Pydantic/PyYAML,
Pytest/Ruff and optional Matplotlib/PyArrow remain unchanged.

Baseline inspection: 68 tests passed on November 3, 2026 (6.68 seconds).
Existing pieces: supporter/membership/club/proposal/result objects; independent and
Gaussian-copula populations; four weight strategies; canonical eligibility; probabilistic
turnout/preferences; registry/protocol injection; paired trials; CSV/JSON/Parquet/plots.
Missing: expanded traits/history, affordability, constant/categorical built-ins,
hybrid/expertise, richer behavior, proposal overrides, representation, full baseline artifacts.
No duplicate subsystem or unfinished skeleton needs replacement.

## Work sequence

1. Extend config without breaking old YAML. Add richer population configuration and
   supporter aliases, distributions, forecast records and financial constraint modes.
   Preserve old internal attribute names; accept Phase 2 names as aliases.
2. Independently extend voting formulas/hybrid/expertise and turnout/preference plugins.
   All keep existing protocols; category/metadata extend VotingContext with defaults.
3. Wire proposal-specific governance and registries. Introduce immutable matched snapshots
   carrying eligibility and realizations; pin a strategy-neutral proposal for behaviors.
4. Add electorate/wealth representation, realized power and equal-counterfactual metrics.
   Extend experiment axes, keep scenario/trial pairing and scientific provenance.
5. Add six population profiles, six-model/two-category 100-trial baseline, complete
   baseline exports/summary, optional research figures and standalone benchmark commands.
6. Run original/new tests, lint, build/install check; execute baseline and three requested
   benchmarks, record actual results/memory/environment; update documentation.

## Design decisions and review focus

- No extra IDs: fan_id aliases supporter_id; knowledge_score and participation_rate alias
  existing fields. Defaults allow old construction. Traits remain synthetic assumptions.
- Contribution affordability defaults to clipping independent draws to wealth. A named
  allow_unfunded mode explicitly permits an alternative. Wealth-fraction generation is
  separately configured; effects on marginal distributions/correlation are documented.
- Preserve Phase 1 voting constructor keywords and formulas. New formula parameter names
  opt into Phase 2 normalized/baseline/capped formulas; baseline config is fully explicit.
- Expertise uses synthetic correct/total histories and conservative evidence above a
  chance baseline; insufficient history gets neutral weight. Knowledge is never evidence.
- Proposal overrides are merged by the composition root; no voting-model branches in loop.
- Binary threshold/tie/abstention conventions remain compatible and documented.
- New metrics must distinguish eligible potential power from valid participating power.
- Validate alias conflicts, PSD/symmetry/diagonal, immutable snapshots, ordering independence,
  zero/empty denominators, plugin errors, partial histories, and controlled category routing.

Execution will be incremental, with isolated file ownership for independent agent work,
followed by full-suite integration and independent review.

## Execution ledger

- Population, voting and behavior modules implemented through existing extension points;
  focused deterministic tests verified each component before integration.
- All original assertions retained. Financial constraints required two old test fixtures
  to declare enough wealth for their membership records; this is intentional Phase 2
  domain tightening, not removal of coverage.
- Added explicit immutable input snapshots; eligibility called once, selected records
  passed to behavior, and original-club mutations cannot alter prepared elections.
- Independent review found actual seed-provenance, authoritative-member affordability,
  and inactive-duplicate behavioral-record bugs. Failing regressions reproduced each;
  focused tests and reviewer verification confirmed fixes.
- Added regression for standalone proposal voting override labels and corrected shared
  effective-voting-spec composition. Constant turnout now has a common default of .6.
- Integrated suite: 191 passed, 92% statement coverage. Ruff clean; source/wheel build
  succeeded. Final packaging verification and measured evidence are in PHASE2_RESULTS.md.
- Full reviewed baseline executed 1,200 elections (100 trials x 10k supporters x six
  models x two categories), generated all requested baseline artifacts and six figures.
- Three isolated-process workloads measure runtime and absolute peak RSS; report retains
  their exact configurations, source hash, environment, rows and measurement method.
- No new dependencies, frontend, blockchain, transactions, attack scenarios or economic
  ledger. Only documentation/examples are edited after final source-hashed experiment.
