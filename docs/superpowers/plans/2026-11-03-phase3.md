# Phase 3 implementation plan

Goal: configurable synthetic attacks, defenses and multi-period club economics around
the existing six-model engine. Spec: docs/PHASE3_REQUEST.md. No live systems or money.

Baseline: 191 tests passed before modification (16.81s). Existing Phase 2 protocols,
registry, population generation, immutable election snapshots, six vote strategies,
representation metrics, exports and optional plotting are functional. No attack,
identity-resolution, lifecycle or financial-ledger subsystem exists to duplicate.

1. Define event/actor/resource/identity/account state and strategy contracts; calendar
   scheduler and membership lifecycle. Preserve Phase 2 public interfaces.
2. Independently implement seven event-producing attacks, composable defenses and
   a vectorized supporter/club economics module with four composable shocks.
3. Compose them through validated scenario configuration and registries; central
   transition execution enforces budgets and explicit event ordering. Adapt identity
   resolution to the original engine without weakening canonical deduplication.
4. Add weighted quorum through the existing metrics/runner boundary; account for
   count quorum, approval, rights/control and economic cash flows separately.
5. Run paired no-attack/unprotected/defended variants with common random streams;
   measure capture objectives, defense errors/costs and financial resilience/quantiles.
6. Create eleven reusable scenarios and seven baseline experiment grids; add offline
   CSV/JSON/Parquet outputs, event histories, time series and eight synthetic figures.
7. Verify original/new analytical/integration/accounting/reproducibility tests, review,
   build/install, run all seven baselines and representative multi-year benchmarks;
   document actual measurements, assumptions, limitations and Phase 4 priorities.

Ordering per simulated date: expire/recover/age -> scheduled attack actions -> identity
verification -> evidence/review safeguards -> economic updates/renewals/shocks -> election.
Economic policy effects and standard governance defense settings are derived anew each
period; multiplicative shocks apply once per variable and recover without compounding
their level reductions into subsequent periods. Event priority ties are stable by sequence.

Financial conventions: contributions are financing cash flows, membership fees and
operating receipts are revenue; borrowing/principal and transfers are separate flows.
Money spent by attackers is finite; only accepted contributions reach the club. Never
count a starting/historical contribution again in each period. Investor rights are
explicit and independent of economic ownership. Cash and profit reconcile separately.

Identity conventions: true people, claims, memberships and credentials are explicit.
Strong verification resolves duplicates to the same person; abstract false acceptance
can produce distinct *perceived* identities in a projected election. Truth is retained
for metrics. Monitoring alerts alone cannot restrict voting; confirmed review is needed,
restrictions expire, and recovery precedes same-date voting.

Independent modules will be delegated with file ownership, followed by integrated tests
and an independent review. Full specification execution is authorized by the user.
