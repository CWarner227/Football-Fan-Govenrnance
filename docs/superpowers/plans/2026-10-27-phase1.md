# Phase 1 Implementation Plan

**Goal:** A standalone, extensible scientific simulation of fan governance.
**Architecture:** Typed domain objects and validated YAML configuration, injected protocols,
registry-based construction, component-specific seeded streams, paired strategy comparisons.
**Tech stack:** Python >=3.12, NumPy, Pandas, Pydantic, PyYAML, Pytest, Ruff;
Matplotlib and PyArrow optional.
**Spec:** User-supplied Phase 1 prompt, retained in docs/PHASE1_REQUEST.md.

## Global constraints

- No frontend, database, blockchain, or future-phase behaviors.
- Full eligible electorate determines concentration; participation determines cast votes.
- Zero and empty denominators are explicitly undefined (JSON null).
- Same population, eligibility, turnout draws, and preferences across strategies in each trial.

## Review focus

- Duplicate identities cannot gain power via duplicate membership records.
- Invalid plugin weights or preferences fail explicitly rather than corrupting totals.
- Zero-weight voters cannot approve a proposal without valid cast weight.
- Configuration typos and invalid distribution parameters fail before execution.
- Strategy order and unrelated component changes cannot perturb random streams.

## Tasks

1. Domain/configuration/population: write validation and reproducible-generation tests;
   implement core/config.py, domain models, agents/generator.py, core/context.py.
   Verify bounds, all four marginals, explicit rank correlation, empty populations.
2. Mechanisms: write formula and eligibility tests; implement voting protocols/four
   strategies, canonical eligibility, turnout, synthetic preference, and registry.
   Verify [0,10,100] weights, waiting boundaries, and duplicate records.
3. Election/metrics: write hand-calculated aggregation and concentration fixtures;
   implement independent metric calculator and dependency-injected engine.
   Verify quorum, approval, invalid ballots, empty/zero-weight cases, custom models.
4. Experiments/output/CLI: test paired comparisons, independent streams, YAML loading,
   grid expansion, CSV/JSON completeness, and executable CLI; implement orchestration,
   exporters, optional plots, example configuration files and library example.
5. Documentation/verification: document interfaces, assumptions, installation, extensions;
   run full tests, Ruff, install/build and end-to-end CLI; execute 100 trials x 10,000
   supporters x four strategies, retain actual outputs and measured summary.

## Rulings and execution record

- User explicitly requests a brief design summary followed by implementation; proceed inline.
- Use the empty workspace itself as repository root; no nested checkout is needed.
- Quorum is eligible-member count based; approval is inclusive weighted threshold among
  valid binary votes, positive total weight required. Ties have no winning option and
  may satisfy a 50% approval threshold. This convention is documented explicitly.
- Membership contribution is authoritative for voting; supporter contribution is a
  population-generation attribute. Duplicate eligible records select the lexically first
  member ID deterministically; identity uniqueness is simulated, never real-world proof.
- Correlations use Gaussian-copula rank reordering, preserving sampled marginals;
  configured values describe latent Gaussian correlations, not exact Pearson output values.

## Verification ledger

- Tasks 1–4 implemented with deterministic unit/integration tests and library/CLI examples.
- Task 5: documentation written; packaging, console entry point and optional exports/plots
  exercised. See docs/VALIDATION.md and docs/DEMONSTRATION.md for final measured evidence.
- Population distributions support injected samplers, not just replacement of the entire
  generator. Custom sampler bounds and nonfinite outputs have explicit regression tests.
- Reviewer identified intermediate c/scale overflow in diminishing voting. The failing
  regression reproduced inf for c=1e308, scale=0.1; stable logarithm evaluation now
  returns the finite expected result. Default formulas remain mathematically unchanged.
- Fixed a custom-distribution validation early return that skipped lower/upper checks.
- Protected governance constructor inputs against duplicate parameter overrides.
- Environment ruling: the sandbox blocked uv executable creation; approved setup created
  a project-local environment. Pytest's default system temp directory was also blocked;
  verification uses a workspace-local --basetemp. Neither requires product-code changes.
- Serena symbol tools were unavailable because no language server was configured;
  ordinary file tools were used after attempted semantic reads/edits failed.
